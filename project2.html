CODELENS-X

Project Overview

CodeLens-X is a hybrid C/C++ code analysis system that combines LLVM's clang-tidy static analysis with a Python processing pipeline and LLM-based explanation layer. The system processes compiler diagnostics, converts raw warnings into structured issue data, and generates human-readable explanations including severity information, potential impact, and suggested fixes. The goal of CodeLens-X is to improve the readability and understanding of compiler feedback, helping developers identify and resolve C/C++ issues more effectively.

GitHub Repository

Key Features

  • Integrates LLVM clang-tidy to perform static analysis on C/C++ source code
  • Parses compiler diagnostics into structured issue data including file location, rule, severity, and message details
  • Implements a multi-stage workflow: static analysis → parsing → categorization → AI explanation
  • Uses LLM-based explanations to provide clearer descriptions of detected issues, potential impact, and suggested fixes
  • Applies consistent severity classification to organize and prioritize detected warnings
  • Generates structured debugging reports to improve understanding of compiler feedback
  • Provides an interactive Streamlit interface for code analysis and report visualization

How It Works

The system accepts C/C++ source code through a Streamlit interface and prepares the input file for static analysis.

LLVM clang-tidy analyzes the source code and produces compiler diagnostics containing detected warnings, rule information, and source locations.

A Python processing layer parses the clang-tidy output and converts raw diagnostics into structured issue data, including file location, rule ID, severity, and diagnostic messages.

Extracted issues are passed to an LLM-based explanation layer (GPT-4.1-mini), which generates clearer descriptions of the issue, potential impact, and suggested fixes.

The processed results are displayed through a Streamlit dashboard as an organized debugging report with issue summaries and detailed analysis.

Challenges & Solutions

clang-tidy diagnostics varied across warning types
Solution: Developed a Python parsing layer using regex and structured extraction logic to normalize compiler diagnostics into consistent issue data.

PowerShell output redirection produced incomplete clang-tidy logs
Solution: Switched to CMD-based execution with proper stderr redirection to reliably capture compiler output.

Regex parsing needed to support multiple diagnostic formats
Solution: Refined parsing logic to handle Windows file paths, multi-line warnings, and varying clang-tidy output structures.

LLM responses needed consistent formatting for downstream processing
Solution: Designed structured prompts and controlled output constraints to generate consistent debugging explanations.

The system needed to process multiple diagnostics efficiently
Solution: Implemented an iterative processing pipeline to analyze batches of clang-tidy issues within a single workflow.

Integrating analysis, parsing, AI, and visualization into a single application
Solution: Designed a modular pipeline architecture separating static analysis, processing, explanation, and presentation layers.
